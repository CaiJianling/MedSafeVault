# MedSafeVault · 医安密管平台

面向医院信息科的**本机密码与资产台账**。服务器、网络设备、应用系统、数据库的账号集中管理，全部数据只保存在这台电脑上，字段级加密、可撤回的修改历史、恢复密钥和自动锁定，为日常运维留下一份可靠底账。

原 tkinter 原型 `密码管理3.py` 的重构版本：Python + pywebview 负责本地服务与加密，React 19 + HeroUI v3 负责界面。

## 1. 功能一览

**台账与页面**

- 多标签页管理，内置「服务器 / 网络设备 / 应用系统 / 数据库」四类模板，也可从空白页或模板新建自定义页；每页可自由增删列、改列名、改列类型（文本 / 多行 / 数字 / 日期 / 账号 / 密码 / 链接 / 命令）。
- 列可拖拽排序、冻结、隐藏，超过 10 列时新增列会自动滚动到新列与底部添加按钮。
- 搜索框跨列模糊检索，支持按列筛选；行右键菜单可复制、编辑、连接、删除；行首多选框支持批量复制与批量移入回收站。
- 手动排序：行最左侧是拖动手柄，按住即可把该行拖到任意位置（拖动中显示插入位置横线），手柄聚焦后还可用 Alt+↑/↓ 逐行移动；顺序存在记录的 `sort_order` 列里，重启后保持，并可整体撤回/重做。列排序（点列标题）是另一种视图，第三次点击会取消列排序回到手动顺序，列排序期间拖动手柄会置灰。行右键菜单保持精简（编辑/连接/复制/选择/回收站），不掺排序操作。
- 外观：页面设置里可以给**标签页**挑一个颜色（图标、计数、下划线与标签下方那块**页面说明区**都跟着变）；记录编辑里的「行外观」
  可以给这一行单独设**背景色**与**文字颜色**（只影响列表显示，不改数据），方便把重点系统标出来。
  三处取色都用 HeroUI 官方 `ColorPicker`（预设色板 + 取色区 + 色相滑杆 + 十六进制输入），另有「默认」还原，颜色存成 `#RRGGBB` 写进库（schema v5）。
  设了背景色的行会自动反色：文字按底色亮度取近黑/近白，行内的按钮、掩码圆点、占位破折号、链接强调色都从这支前景色派生。
- 分页（每页 10/20/50/100 条 + 跳转页码）、紧凑行高、等宽字体列表。
- 输入框历史值联想：操作系统、厂商等列会提示本机已录入过的值（密码列永不联想）。

**安全**

- 打开密码（主密码）加解密，密码本身不落库；首次打开默认跟随系统的亮/暗主题（之后以密码库中记录的选择为准）；自动锁定倒计时可配置（0–240 分钟，默认 5 分钟），超时清除内存密钥。
- 所有敏感列字段级加密，密码列使用更高等级的独立子密钥；列表默认掩码显示，逐字段点击小眼睛才能查看，没有「全部显示」。
- 一次性恢复密钥（`.msvkey` 文件或 32 位恢复码）可强制重设打开密码，忘记主密码不会丢数据。
- 可选两步验证：设置 → 安全生成 `otpauth://` 二维码（也可复制 Base32 密钥手动录入），输入一次验证器当前显示的数字即完成绑定；此后每次打开与每次自动锁定后重新解锁都要「打开密码 + 6 位动态验证码」（RFC 6238 TOTP，SHA-1/30 秒/±30 秒容差，纯标准库实现）。验证码密钥用数据密钥加密后存在库里，改打开密码不影响绑定；同一个验证码用过一次即拒绝重放；手机丢失时用恢复密钥重设密码会自动解除绑定，导入备份同样清除绑定。
- 复制密码后剪贴板 30 秒自动清除；修改历史本身也是加密存储，支持撤销/重做与逐条回滚。
- 内置会话只活在内存里：SSH/SFTP/FTP/VNC 密码不落盘，锁定、退出或关闭标签时连接即断开；VNC 画面经 `127.0.0.1` 回环上的 WebSocket 中继进入 WebView2，不额外对外开放端口。
- 回收站保留被删除的记录，可还原或彻底清除；Excel 导入导出模板与列映射（导入预览可逐行勾选，默认全选），导出时可选用**工作簿密码**保护 `.xlsx`（Excel 打开时要求输入）；导入带打开密码的 `.xlsx / .xls` 会先要求输入密码，验证通过才显示预览，解密只在内存中进行；导出备份时设置**备份密码**，整个文件（含页面结构与记录条数）都被它加密，导入时必须先验证该密码才能看到内容。

**连接与工具**

- 每条记录可单独指定连接方式（默认 / SSH / RDP / Telnet / FTP / SFTP / VNC）。选「默认」时按端口判断（5900–5903 VNC、3389 RDP、21 FTP、23 Telnet、22 SSH），再按记录里的操作系统判断（Windows → RDP，其余 → SSH）；地址写成 `host:port` 时以地址里的端口为准。
- RDP 调用系统 `mstsc`：设置里可选自动填充「用户名 + 密码 / 仅用户名 / 不填充」（默认仅用户名）。密码不写进 `.rdp` 文件，只在 mstsc 运行期间写入当前用户的临时凭据，mstsc 退出后立即删除。
- 外部客户端可自动查找，也可在设置里指定路径：SecureCRT（支持带密码打开 SSH/Telnet 会话）、PuTTY、Xshell、Windows 自带 OpenSSH 与 telnet、WinSCP、VNC Viewer；浏览器地址仍可直接打开。
- 内置终端：SSH 终端（xterm 前端）、FTP/SFTP 图形化双栏文件管理（上传、下载、新建目录、重命名、删除、切换本机目录）、VNC 画面（noVNC）。连接后在本窗口弹出全屏浮层，按标签页管理；多个标签时顶栏「终端」按钮显示数量角标（底色与文字随主题和强调色变化），关闭浮层只是收回按钮、不中断会话；锁定或退出时全部断开。浮层打开/收起从顶栏「终端」按钮位置做 Material 风格的圆形扩散与反向收拢，不加暗色遮罩，面板四周仍能看到原页面；系统「减少动态效果」开启时自动近乎瞬时。
- 关闭窗口有两种行为：最小化到小图标区（托盘）或直接退出。默认每次关闭都询问，可在弹窗里「记住我的选择」（勾选框与列表、导出弹窗使用同一套样式），也能在设置里改回每次询问。托盘小图标右键菜单提供打开主界面、锁定密码库、退出。
- 单实例运行，重复启动会把已隐藏的窗口叫回前台。窗口第一次打开时最大化，关闭时记下位置和大小（连同所在显示器的分辨率），下次启动按上次关闭的样子打开；如果分辨率变了、记录的位置已经不在任何屏幕范围内、或窗口只剩一小截露在外面，就退回最大化；恢复时按当前工作区夹取，最小 1140×700 与任务栏都会让窗口整块留在屏幕里，不会出现看不到窗口或内容溢出屏幕的情况。记录写在 `<数据目录>/window.json`，只是界面状态，不含任何密钥。
- 亮/暗/跟随系统三态主题、8 套预设强调色 + **HeroUI 官方取色器自选颜色**、界面大小（小/标准/大）、界面字体与代码字体（读取系统字体）、中英文界面（跟随系统，可手动切换）；自选强调色时正文/图标里的强调色会自动调深或调浅到看得清，实心按钮的标签按底色亮度在黑与白之间自动反色；主题与配色存在密码库里，换机或换用户配置后打开仍是原来的样子。
- 内置帮助说明（顶栏问号，锁屏与首次设置页也有入口）：14 个小节覆盖加密模型、恢复密钥、两步验证、数据目录搬移、备份迁移、Excel、远程连接、内置终端与托盘、列表与快捷键、内网自动更新、环境变量、老旧终端部署与常见问题，中英文同稿。
- 内网自动更新：`update/server.py` 是纯标准库的院内更新服务，一个端口同时提供**给应用用的只读接口**（`/api/version`、`/api/releases`、`/download/<版本>`、`/healthz`）和**给信息科用的管理后台**（浏览器打开根路径就是 HeroUI 页面：账号口令登录、拖拽上传 exe、填版本号发布、设为最新回滚、下架、看最近操作，并直接给出「应用设置里该填的地址」）。版本与安装包位置写在 `update/versions.json`，也可以用 `update/make_release.py` 命令行登记（自动算大小与 sha256）。在 设置 → 关于 → 更新服务地址 填好地址后，每次打开应用自动检查一次，发现新版即提示；更新说明支持 **Markdown**（标题、列表、粗体、行内代码、代码块、引用、表格，普通换行保留），写长了在弹窗里内联滚动，不会把提示框撑开。选「以后再说」时，顶栏设置按钮与 设置 → 关于 标签右上角会各带一个红点；关于页在版本号后面显示最新版，并提供「更新内容 / 立即更新」两个入口，点「立即更新」直接在弹窗里开始下载。确认后下载到数据目录的 `updates/`，按 sha256 与大小校验，再由分离的后台助手（`--apply-update`）等本进程退出、把旧版本留成 `MedSafeVault.exe.old`、替换并重启，全程不需要管理员权限、不写注册表、不访问外网；地址留空就完全不检查。服务端部署见 `update/README.md`（Linux 上 `python3 update/server.py` 即可，无第三方依赖）。

## 2. 架构

```
MedSafeVault.py            入口脚本（等价于 python -m backend.main）
backend/                   Python 侧：加密、存储、桥接
  crypto.py                AES-256-GCM / PBKDF2 / HKDF，两层密文格式
  totp.py                  RFC 6238 动态验证码（纯标准库：HMAC-SHA1、Base32、otpauth URI）
  store.py                 VaultService：库、页、列、记录、历史、回收站、备份、设置、两步验证
  api.py                   暴露给前端的 js_api 门面（95 个方法）
  updater.py               客户端更新：版本比较、下载与 sha256 校验、--apply-update 替换重启
  excelio.py               xlsx / xls / csv 读取与导出
  remote.py                外部程序启动：mstsc、SecureCRT、PuTTY、Xshell、WinSCP、VNC Viewer
  sessions.py              内置会话：SSH、FTP/SFTP、VNC 中继（仅内存）
  tray.py                  托盘小图标与右键菜单
  clipboard.py             Win32 剪贴板 + 定时清除
  paths.py                 资源目录 / 数据目录
  window_state.py          窗口位置记忆：GetWindowPlacement + <数据目录>/window.json
  main.py                  单实例、日志、pywebview 窗口、窗口位置与尺寸适配
web/                       React 19 + TypeScript + Vite + Tailwind 4 + HeroUI 3
  src/lib/api.ts           统一调用层：原生桥 / 浏览器演示模式
  src/lib/i18n.tsx         中文源串作键的中英文词典 + 后端文案翻译
  src/components/          锁屏、标签页、表格、抽屉、弹窗、设置等
tools/                     图标生成、打包、桌面/CDP 截图、自检脚本
update/                    院内更新服务（独立部署，不进 exe；Linux 上 python3 直接跑）
  server.py                一个端口全包：更新接口 + 管理后台 + 静态页面 + 断点续传下载
  admin.py                 登录凭据（PBKDF2）、会话与限速、上传暂存、静态托管、/api/admin/*
  common.py                版本号、sha256、JSON 原子写等公用小函数
  make_release.py          命令行登记：把 dist/MedSafeVault.exe 写进 versions.json
  versions.json            版本表：版本号 ↔ 该目录下的安装包相对位置、说明、是否必须更新
  requirements.txt         依赖说明（结论：只用标准库，pip 装不了东西）
  README.md                部署手册：systemd、防火墙、nginx、忘记口令、常见问题
  admin.json               管理后台凭据（首次启动自动生成，.gitignore 已忽略）
  files/                   等待分发的安装包（.gitignore 已忽略，不进版本库）
  web/                     管理页面源码（Vite + React 19 + Tailwind 4 + HeroUI 3）
    dist/                  构建产物，由 server.py 托管（入库，服务器上不需要 Node）
```

前后端只通过 pywebview 注入的 `window.pywebview.api.<method>()` 通信，返回值统一为 `{ok: true, ...}` / `{ok: false, error, locked?}`；前端在 `ApiError` 一处集中翻译后端文案。默认不监听网络端口，`http_server` 只在回环地址上为 WebView2 提供静态资源；只有内置 VNC 会话会在 `127.0.0.1` 上临时开一个 WebSocket 中继（端口随机，会话关闭即释放），调试端口仅在 `MSV_DEBUG=1` 时开放。

在纯浏览器（无原生桥）下会退化为演示模式：`src/lib/mock.ts` 用内存数据实现同一套接口，方便截图与 UI 校验，数据不落盘。

## 3. 开发

开发环境为 Python 3.13（64 位）+ Node.js 20+；更低版本未做兼容验证（Win7 需要独立的 3.8 工具链，见第 7 节）。全程不写注册表、不需要管理员权限（代码中无任何 `winreg` 调用）。

```bash
# 后端依赖（项目内虚拟环境）
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt

# 国内镜像
.venv\Scripts\python.exe -m pip install -r requirements.txt ^
  -i https://pypi.tuna.tsinghua.edu.cn/simple

# 前端
cd web
npm install --registry=https://registry.npmmirror.com
npm run build          # 产出 web/dist，供 backend/main.py 直接加载
```

两种运行方式：

```bash
# 1) 加载已构建的前端（最接近发布形态）
npm run build --prefix web
.venv\Scripts\python.exe MedSafeVault.py

# 2) 前端热更新：先起 Vite，再让桌面端指向它
cd web && npm run dev
set MSV_DEV_URL=http://localhost:5179
..\.venv\Scripts\python.exe MedSafeVault.py
```

`MSV_DEBUG=1` 打开 WebView2 的远程调试端口（`MSV_DEBUG_PORT`，默认 9222，开发者工具窗口不自动弹出），可配合 `tools/cdp_shot.mjs` 驱动真实窗口做截图回归。自检脚本：`tools/selftest.py` 无界面验证加密、导入导出、历史与手动排序（含子集拖动、撤回/重做、空操作不写历史）；`tools/test_schema_migration.py` 用真的把 `sort_order` 与颜色列都删掉的旧库验证 v3→v5 升级不报错、原顺序不变、升级后能拖动、颜色列按空默认补齐且能正常读写；`tools/test_location.py` 在临时目录里跑完数据目录搬移的全部分支；`tools/test_backup.py` 验证备份封套的加解密、错误密码、旧格式兼容与恢复后主密码仍可用；`tools/test_excel.py` 验证带密码的 xlsx 导出/预览/导入与加密旧式 `.xls` 的解密导入（含无密码、错误密码与损坏文件分支，样本在 `tools/fixtures/`），并检查所有文件对话框过滤器都能被 pywebview 解析（标签只允许字母/数字/下划线/中文/空格，模式必须以 `*` 开头）；`tools/test_connect.py` 覆盖连接方式推断（端口、`host:port`、操作系统）、设置持久化、FTP/SFTP 列表解析、本机目录、VNC 中继与 SSH 会话的建立/读写/关闭，以及锁库时统一断开；`tools/check_i18n.py` 扫描界面字符串，缺英文词条就报错（退出码 1）；`tools/test_theme_contrast.py` 从 styles.css 解析 8 套强调色、`--msv-solid-*` 派生令牌与危险色，按浏览器的方式算出实心按钮两档渐变色与前景色，核对 16 种组合的对比度、暗色浅色系「不许用白标签」的反向断言、暗/亮两套正文色阶在真实面板底色上的对比度，并扫描组件里是否又出现写死的 `text-white`；`tools/test_window_state.py` 用假桌面指标覆盖窗口位置记忆的判定分支（首次最大化、原样恢复、分辨率变化、位置越界、最小尺寸与 125% 缩放、双屏、坏记录）。`tools/desktop_shot.ps1` 启动真实窗口、模拟粘贴/按键并截取窗口位图，用于桌面端回归（注意它必须先声明 DPI 感知，否则截到的只是窗口左上角）。

> 维护提示：pywebview 在注入 `window.pywebview.api` 之前会递归遍历 `js_api` 对象的每个**公开**属性。因此 `backend/api.py` 的 `Api` 只能暴露方法，服务与窗口引用必须写成 `_service` / `_window` / `_attach`；否则它会顺着引用爬进 sqlite 连接和整个 WinForms/WebView2 对象树，UI 线程被占用数十秒并抛出「maximum recursion depth exceeded」，前端表现为「本地服务未就绪」。

产物为 `dist/MedSafeVault.exe`（onefile、无控制台窗口、不压缩 UPX），构建结束会打印体积与 sha256。配置见 `MedSafeVault.spec`：打包 `web/dist` 与 `assets`，收集 `webview` 全部子模块（`edgechromium` / `winforms`）、`clr`、`bottle`、`openpyxl`、`xlrd`、`olefile`、`msoffcrypto` 的格式化/加密法子模块，以及 `paramiko`（含 `bcrypt` / `nacl`）、`websockets`、`pystray` 与 `PIL.Image`/`ImageDraw`；版本信息来自 `packaging/version_info.txt`。

当前产物 **27.1 MB**，`sha256 831e725b2365fec0963a833de3eaa312d672fc9988e6e1bcfba28e802932d2c3`（Python 3.13 x64 构建，已在真机完成启动、解锁、内置终端与关闭/托盘流程验证，见第 9 节）。换机器或改依赖后重新构建，以脚本打印值为准。

免管理员说明：onefile 解压到 `%TEMP%`，数据写入 `%APPDATA%\MedSafeVault`，不写注册表、不需要安装运行库，拷到任意可写目录即可运行。

### 版本号怎么改

版本号只有两处真源，改完必须互相对齐（不会自动同步）：

1. **`backend/__init__.py` 的 `__version__`** —— 唯一的功能性来源。设置 → 关于 里显示的「版本」、更新时与版本表比较的「当前版本」（`backend/updater.py` 靠它决定要不要提示更新）、请求更新服务的 User-Agent、日志里的 `Starting MedSafeVault …`，以及更新服务管理页面标题栏上的「桌面端 x.y.z」（`update/server.py` 直接对这个文件正则取值，不 import 后端）都读它。格式是点分数字，最多四段：`2.1.0`、`2.1`、`2.0.0.1` 都合法，比较时按四段数字补齐（`2.1` 等同 `2.1.0`）。
2. **`packaging/version_info.txt`** —— exe 右键属性里的「文件版本 / 产品版本」，由 `MedSafeVault.spec` 第 93 行喂给 PyInstaller。同一个版本号在这个文件里要改四处：`filevers=(2, 0, 0, 0)`、`prodvers=(2, 0, 0, 0)`（四段数字元组，末段一般是 0）、`FileVersion` 与 `ProductVersion`（字符串）。

改完重新打包并核对两边一致：

```bash
.venv\Scripts\python.exe tools\build_exe.py
.venv\Scripts\python.exe -c "import backend; print(backend.__version__)"   # 源码里的版本
powershell -NoProfile -Command "(Get-Item dist\MedSafeVault.exe).VersionInfo | Format-List FileVersion,ProductVersion"
```

发布这一步别漏：新版本要登记进更新服务，否则老客户端检查不到更新——管理后台上传发布，或命令行 `python update/make_release.py --exe dist/MedSafeVault.exe --version 2.1.0 --notes "这次改了什么"`。同时把 `README.md` 上面那行「当前产物体积 / sha256」按构建脚本打印的新值更新（构建结束会打印），并在第 9 节补一段验证记录。

文档里其他出现 `2.0.0` 的地方（`update/README.md` 的示例输出、帮助页的 `GET /api/version?current=2.0.0`、管理页面自测框的 placeholder、`tools/test_*.py` 里的用例）都只是举例，不随版本走，不用改。

## 5. 安全模型

| 项 | 取值 |
| --- | --- |
| 数据密钥 DEK | 随机 256 位，加密所有敏感字段 |
| 主密码派生 | PBKDF2-HMAC-SHA256，600,000 次迭代，随机 16 字节盐 |
| KEK 用途 | 仅包裹 DEK（AES-256-GCM，绑定 AAD），主密码本身不存储 |
| 字段密文 | `v1:<base64>`，AES-256-GCM，AAD `medsafe-vault/field/v1` |
| 密码字段 | `s1:<base64>`，密钥为 DEK 经 HKDF-SHA256（info `password-subkey/v1`）派生的子密钥 |
| 完整性校验 | 解锁时用 DEK 加密固定串验证，密钥错误立即失败 |
| 恢复密钥 | 独立 PBKDF2 派生的第二把 KEK，包裹同一个 DEK；文件绑定 `vault_id` 与代数 |
| 两步验证 | 可选 TOTP（RFC 6238，SHA-1 / 30 秒 / 6 位 / ±1 步）。共享密钥随机 20 字节，用 DEK 加 AAD `medsafe-vault/totp/v1` 密封后存在 `meta` 表；解锁时先验密码再验验证码，失败不装入密钥；同一 (验证码, 步数) 拒绝重放 |
| 修改历史 | 与记录同库存储，diff 亦为密文 |
| 备份封套 | `MedSafeVault.EncryptedBackup`：PBKDF2-HMAC-SHA256（600,000）派生备份密钥，AES-256-GCM 加密整个备份文档，并额外用该密钥包裹 DEK |
| Excel 工作簿密码 | 导出可选，ECMA-376 agile 加密（AES-256 + SHA-512，msoffcrypto-tool 实现），只保护 `.xlsx` 文件本身，与保险库密钥无关；导入加密的 `.xlsx / .xls` 时在内存中解密，密码不落盘 |

两层密文的意义：拿到 `vault.db` 且破解了普通字段密钥，仍需再派生一次才能读密码列。旧版本遗留的明文值会在下次解锁时自动重新封套（at-rest sweep），不改业务代码。

改主密码只重新包裹 DEK，历史密文与所有字段密文保持有效，无需全库重写。开启两步验证后同样如此——验证码密钥跟着 DEK 走，改密码不需要重新扫码。

**两步验证的两个设计点**：一是密码与验证码合用时失败提示统一为「打开密码或动态验证码不正确」，否则密码猜对时提示会变成一条可用的判定依据；二是恢复密钥与导入备份都会清除验证码绑定，因为恢复流程本身已经证明了对库的访问权，而手机丢失或换机不该让数据永久打不开（界面与帮助里都写明了这一点）。

**威胁模型边界**：本机防御性存储，不是保险柜级。解锁期间密钥在进程内存中，内存转储、键盘记录、以及 `%APPDATA%` 目录的文件读取权限都在防护范围之外。请保证 Windows 账户口令强度、开启 BitLocker，并把 `.msvkey` 存到与本机隔离的地方。

## 6. 数据位置与环境变量

数据目录有三种选择（设置 → 数据 → 数据目录），**改完重启生效**，退出时自动搬移：

| 模式 | 实际位置 | 用途 |
| --- | --- | --- |
| `%APPDATA%\MedSafeVault` | `%APPDATA%\MedSafeVault` | 默认，普通用户可写 |
| 应用程序所在目录 | `<程序目录>\MedSafeVaultData` | 数据随程序走，U 盘/共享盘 |
| 自定义目录 | 手填或浏览选择 | 加密盘、信息科指定位置 |

位置写在程序目录下的配置文件 `MedSafeVault.json`（首次启动自动生成）：

```json
{
  "version": 1,
  "data_location": { "mode": "appdata", "path": "C:\\Users\\…\\MedSafeVault" },
  "pending_location": { "mode": "portable", "path": "D:\\…\\MedSafeVaultData", "requested_at": "…" }
}
```

程序目录不可写（例如装在 `C:\Program Files`）时，配置文件自动改存 `%APPDATA%\MedSafeVault\MedSafeVault-location.json`；全程不写注册表。

搬移在 `webview.start()` 返回、数据库连接与日志句柄释放之后执行：复制 `vault.db`/`app.log`/`*.msvbackup` → 对新库跑 `PRAGMA integrity_check` → 改写配置文件 → 把旧目录改名为 `…-旧数据-<时间戳>` 保留（绝不直接删除），最后弹窗告知结果。`webview/` 是浏览器缓存，不参与搬移，会在新位置重建；改名遇到文件占用会重试约 4 秒，仍失败则保留原目录并在弹窗中提示手动删除。

数据目录内容：

```
vault.db          加密台账（SQLite，WAL 模式）
vault.db-wal/-shm 运行期临时文件，退出后自动合并
app.log           运行日志（1.5 MB × 3 轮转）
webview/          WebView2 用户数据
*.msvbackup       加密备份（含「恢复前自动备份」）
```

| 变量 | 作用 |
| --- | --- |
| `MEDSAFE_DATA_DIR` | 强制指定数据目录，优先级高于设置页；设置后本页选项变灰 |
| `MSV_DEV_URL` | 让桌面端加载 Vite 开发服务器 |
| `MSV_DEBUG` | `1` 打开 WebView2 远程调试端口（不弹开发者工具窗口） |
| `MSV_DEBUG_PORT` | 调试端口，默认 9222 |

备份与迁移：设置 → 导出完整备份时输入备份密码，得到整体加密的 `.msvbackup`；导入时先「验证并预览」再覆盖恢复，恢复前会自动留一份当前数据的备份。恢复密钥 `.msvkey` 请单独保管。整目录拷贝即完成迁移。

备份密码与打开密码相互独立：忘记打开密码可用恢复密钥重设；忘记备份密码则该备份文件无法读取（旧版未封套的 `.msvbackup` 仍可用当时的打开密码恢复）。

### 更新服务（update/）

院内自建的一个小网站：同一个端口既给桌面端提供更新接口，也给信息科提供带登录的管理后台。纯标准库，Python 3.8+ 即可运行，不需要任何第三方包（`update/requirements.txt` 里解释了为什么不装东西），也不需要管理员权限；完整部署手册见 `update/README.md`。

```
update/
  server.py          入口：更新接口 + 管理后台 + 静态页面 + 断点续传下载
  admin.py           登录凭据（PBKDF2）、会话与失败限速、上传暂存、静态托管、/api/admin/*
  common.py          版本号、sha256、JSON 原子写
  versions.json      版本表：版本号 ↔ 本目录下的安装包相对位置、说明、大小、sha256、是否必须更新
  make_release.py    命令行登记（复制 + 算 size/sha256 + 更新 latest），不想开网页时用
  requirements.txt   依赖说明（结论：只用标准库）
  README.md          部署手册：systemd、防火墙、nginx、忘记口令、常见问题
  admin.json         首次启动生成的管理员凭据（只存散列，.gitignore 已忽略）
  files/             等待分发的安装包（体积大，已在 .gitignore 中忽略）
  web/               管理页面源码（Vite + React 19 + Tailwind 4 + HeroUI 3），dist/ 是入库的构建产物
```

启动与发布：

```
python update/server.py --host 0.0.0.0 --port 8000 --username admin --password '至少 8 位'
python update/server.py --port 8000 --throttle 2500000   # 限速 2.5 MB/s，用来在慢速链路下看客户端进度
python update/server.py --set-password                   # 忘记口令时在服务器上重置
python update/make_release.py --exe dist/MedSafeVault.exe --version 2.1.0 --notes "更新说明"
```

浏览器打开 `http://<服务器IP>:8000/` 就是管理后台（HeroUI 3，与桌面端同一套主题与控件）：登录 → 把 exe 拖进上传框（请求体就是文件本身，边传边算 sha256，先落 `files/.uploads/`）→ 填版本号与更新说明 → 发布，服务端把文件搬进 `files/` 并把 size/sha256 写进 `versions.json`；也可以选「用已有文件」直接登记 scp 进来的构建产物。列表里能设为最新（回滚）、改说明、切必须更新、下架（可选连文件一起删），并给出「桌面端设置里该填的地址」和一键自测。口令只存 PBKDF2-SHA256 散列，会话是 HttpOnly Cookie，同一 IP 连错 5 次锁定 5 分钟，写操作额外要求页面自带的 `X-Msv-Requested-With` 头。

终端侧：设置 → 关于 → 更新服务地址 填 `http://<服务器IP>:8000/`（也可以直接填到 `/api/version`），回车或点到别处即保存；填了地址后每次打开应用自动检查一次，也可以随时点「检查更新」手动验证。检查与下载都只走这个地址，不访问外网，地址留空则完全不检查。

更新过程：应用比对版本号（4 段数字，`2.1` 等同 `2.1.0`），有新版则弹窗列出版本号、大小、sha256、发布时间与说明；点「立即更新」后下载到 `<数据目录>/updates/`，边下边算 sha256，与版本表不符或大小不符直接拒绝安装；下载完成后点「立即重启并更新」，应用再次校验哈希，就地把自身的 exe 改名成 `MedSafeVault.exe.old`、把新包写到原路径，然后拉起一个同 exe 的隐藏副本（`--relaunch-after 4`）并退出：这个副本不开窗口、不弹命令行，等 4 秒（此时上一个进程和解包目录都已清理干净）再把新版本正常启动；替换与重启分别记在 exe 同目录的 `update-apply.log` 与 `update-relaunch.log`。若就地改名被拦（例如安全软件占着镜像），退回由 `--apply-update` 分离助手等本进程退出后再替换。服务端只发送 versions.json 里登记过的文件，路径解析后落在服务目录之外一律拒绝，支持单段 `Range` 请求与 `--throttle` 限速；给桌面端的三个接口（`/api/version`、`/api/releases`、`/download/<版本>`）不需要登录，管理接口全部要求登录，请按院内网段开放并自行限制访问。开发模式（`python MedSafeVault.py`）只提示不替换，避免覆盖源码目录。

## 7. Windows 7 / WebView2 降级说明

**当前 exe 不能在 Win7 上运行**：它由 Python 3.13 x64 构建，而 python.org 官方从 3.9 起不再支持 Windows 7（官方文档明确「若需要 Windows 7 支持，请安装 Python 3.8」）。

Win7 终端要跑本项目，需要一条独立的 32 位工具链：

1. Python **3.8.x（32 位）**，需 SP1 + KB2533623；`cryptography` 选仍提供 `cp38-win32` 轮子的版本，`openpyxl`/`xlrd`/`bottle` 不受影响；`pywebview` 6.2.1 声明 `Requires-Python >=3.8`，但需在真机验证；PyInstaller 6.x 支持 3.8。
2. WebView2 运行时。Edge/WebView2 Evergreen 在 Win7/8.1 的最后一个版本是 **109**，2023 年 2 月后不再获得安全更新。可选：
   - **固定版本（Fixed Version）随应用分发**：把解压出的运行时目录放在 exe 同级，设置环境变量后启动，免安装、免管理员、不写注册表：
     ```bat
     set WEBVIEW2_BROWSER_EXECUTABLE_FOLDER=%~dp0FixedVersionRuntime
     set WEBVIEW2_USER_DATA_FOLDER=%~dp0webview-cache
     start "" MedSafeVault.exe
     ```
     注意固定版本有独立生命周期，需定期换版并自行承担安全更新。
   - **Evergreen 离线独立安装包**（x86）在内部软件源分发；引导程序（Bootstrapper）需要联网，机房离线环境请用独立安装包。
3. 若某台 Win7 终端确实装不上 WebView2：pywebview 可回退 MSHTML（IE11 内核），但本项目使用 React 19、CSS 变量与 `backdrop-filter`，**IE11 下无法运行，这条路径不受支持**。这类终端建议升级 Win10，或以远程应用方式访问已部署的机器。

其他环境约束（Win7/Win10 通用）：不写注册表、不需要管理员权限、不依赖已安装的 Office（Excel 读写由 `openpyxl`/`xlrd` 完成，工作簿密码由 `msoffcrypto-tool` 加解密）、依赖国内镜像离线安装。32 位系统请使用 x86 版运行时与 x86 构建产物。

## 8. 已知限制

- 加密只在字段层，SQLite 结构、列名、记录条数与「名称」列的明文索引可见，用于搜索与排序。
- 恢复密钥每次重新生成后旧文件立即失效；它是访问密码库的等价凭据，请按机密文件管理。
- 自动锁定基于最后操作时间，机器休眠期间的计时以唤醒后的活动为准。
- 最小化到小图标区只隐藏窗口，密码库仍保持解锁；彻底离开座位请用托盘的「锁定密码库」或等自动锁定。个别安全软件会拦截托盘回调，此时仍可从任务栏或重复启动 exe 找回窗口。
- 内置 VNC 走 noVNC 的标准 RFB 画面与键鼠，剪贴板双向、文件传输与音频不支持；需要这些能力请在设置里改用 VNC Viewer（external）。
- FTP 是明文协议，账号与文件内容在网络上可被嗅探；同网段能用 SFTP 就不要用 FTP。
- 外部客户端（SecureCRT / PuTTY / Xshell / WinSCP / VNC Viewer）需要本机已安装，内置 SSH/SFTP/FTP/VNC 与系统 `mstsc` 不依赖它们。
- Excel 工作簿密码只保护导出文件本身，强度取决于密码；采用 ECMA-376 agile 加密（Excel 2010 及以上、WPS 可直接打开）。忘记密码无法打开该文件，但保险库数据不受影响。导入侧可解密带打开密码的 `.xlsx / .xlsm` 与旧式 `.xls`（BIFF8 RC4）；其他厂商私有加密的表格需要先用 Excel 另存为无密码文件。
- 两步验证依赖本机与手机的时钟：两边相差超过 30 秒就会一直验证失败（可容差 ±1 步），请先校准系统时间；同一个验证码用过一次要等下一个才能再用，所以「刚解锁过就立刻关闭两步验证」需要等一次刷新。验证码密钥与库绑定，换机时请把 `.msvbackup` 与验证器一起迁移，或走恢复密钥解除绑定后重新扫码。
- 更新包只做 sha256 与版本号校验，没有代码签名：sha256 能发现下载损坏与半包，但不能证明发布方身份，因此更新服务应当只部署在院内网段、由信息科控制 versions.json 与 `files/` 目录的写入权限。替换下来的旧版本保留为 `MedSafeVault.exe.old`（不自动删除，可手工改名回退），安装包暂存在数据目录的 `updates/`，需要自行纳入备份或清理策略。
- 更新服务的管理后台默认走明文 HTTP（院内网段），要跨机房或对外就按 `update/README.md` 第 6 节挂 nginx 上 TLS；登录会话与「最近操作」都只存在服务进程内存里，重启服务需要重新登录、审计记录清零。管理页面只做中文（面向信息科运维），桌面端仍是中英双语。口令忘记只能在服务器上 `--set-password` 重置，没有远程找回通道。
- 「立即重启并更新」的替换与自动重启都已在本机验证通过（替换在退出前完成，旧版本留成 `.old`；重启由程序自己的一个隐藏副本等几秒后拉起新实例，不弹任何命令行窗口）。2026-11-05 修掉了此前「重启后弹 `Failed to load Python DLL …\Temp\_MEI…\python313.dll`、或者新实例只剩引导进程没窗口」的问题：根因是 PyInstaller 6 的单文件启动器会把 `_PYI_PARENT_PROCESS_LEVEL`、`_PYI_APPLICATION_HOME_DIR` 等变量传给子进程，孙进程继承后跳过解包、去父进程已经删掉的 `_MEI` 目录里加载 python313.dll，现在 `launch_env()` 把它们与 `_MEIPASS*` 一起清掉。界面与帮助仍保留「万一窗口没回来就双击 exe」的兜底说明，但已不再是常态。若在别的机器上遇到杀软拦截就地改名，仍会自动退回 `--apply-update` 分离助手。
- 行颜色：设了底色而没设文字色时按底色亮度自动反色，只设文字色时也会在当前底色上自动调明度（保持色相）；两者都自定义时以操作者的选择为准，不再改写。
- 自选强调色的填充保留用户所选颜色，不做提亮：近黑的强调色在暗色主题下按钮与页面背景会比较接近（标签仍然清晰）。
- 演示模式（纯浏览器）不加密、不落盘，仅用于界面预览，不要在其中输入真实数据。

2026-11-05 修复「更新后重启弹 `Failed to load Python DLL`」：

- **现象**：点「立即重启并更新」后程序退出、新版本就位，但起来的是一个模态错误框——`Failed to load Python DLL 'C:\Users\…\Temp\_MEI00013be82\python313.dll'. LoadLibrary: 找不到指定的模块。`，窗口始终没有出现。同一个问题也解释了更早那句「新实例只剩一个 12MB 引导进程」。
- **根因**：PyInstaller 6 的单文件启动器用一组变量告诉子进程「你已经解包好了」——`_PYI_PARENT_PROCESS_LEVEL=1`、`_PYI_APPLICATION_HOME_DIR=<…>\_MEIxxxxx`、`_PYI_ARCHIVE_FILE`（老版本是 `_MEIPASS2`）。这些变量就在应用进程自己的 `os.environ` 里（用一个 5 行的 onefile 探针实测：冻结进程能看到 `_PYI_APPLICATION_HOME_DIR=…\Temp\_MEI000143682` 等三条）。`launch_env()` 原先只删 `_MEIPASS2`/`_MEIPASS`——在 6.x 上根本不存在，于是 bat 与分离助手都把 `_PYI_*` 原样传给了新实例；新实例的启动器以为父进程还在解包，跳过解包、直接去那个目录加载 python313.dll，而父进程退出时已经把 `_MEI` 删了，就得到上面那个框。
- **修复**：`launch_env()` 改成删除所有 `_PYI_*` 前缀的变量，外加 `_MEIPASS`/`_MEIPASS2`/`PYINSTALLER_RESET_ENVIRONMENT`（以及原有的 `MSV_DEBUG*`）；三处启动（bat、分离助手、开发模式直启）本来就都走这一个函数，所以一起修好。`tools/test_updater.py` 增加断言：人为把这些变量塞进 `os.environ` 后，`launch_env()` 返回的字典里不许残留任何 `_PYI`/`_MEI` 开头的键。
- **验证**（临时沙箱 + 真实 27.0 MB exe，`MEDSAFE_DATA_DIR` 指向临时目录）：一、故意伪造「父进程已退出」的环境（`_PYI_PARENT_PROCESS_LEVEL=1`、`_PYI_APPLICATION_HOME_DIR` 指向不存在的 `_MEIdeadbee`）启动 exe → 复现出同一个 `Error` 对话框、没有主窗口，确认根因。二、同一份环境经 `launch_env()` 清洗后启动 → 6 秒内出现 `MedSafeVault · 医安密管平台` 窗口，遗留变量为空。三、走完整替换路径 `MedSafeVault.exe --apply-update <新包> <目标> 0`：助手退出码 0、目标被替换、`MedSafeVault.exe.old` 生成，约 4 秒后新实例带窗口起来，`update-relaunch.log` 里只剩自删除 bat 那句「找不到批处理文件。」的正常噪音。重新打包后 `dist/MedSafeVault.exe` 为 27.0 MB、`sha256 7976310d…fd34`。

2026-11-05 去掉更新重启时的黑色命令行窗口：

- **现象**：点「立即重启并更新」后，替换完成、旧窗口关闭，屏幕上先弹一个黑色 cmd 窗口停几秒，再出现新版本；用户希望「什么都不弹，等几秒自己重启」。
- **原因**：此前重启交给自删除的 `update-relaunch.bat`，里面用 `timeout /t 4` 等时间。`cmd.exe` 与 `timeout.exe` 都是控制台程序：以 DETACHED_PROCESS 启动时 `timeout` 拿不到控制台，要么直接失败（等于没等），要么由系统另开一个控制台窗口——就是看到的那个黑框。
- **做法**：不再写任何批处理。`relaunch_process()` 改成用 `sys.executable --relaunch-after <秒> <目标>` 拉起**自己的一份隐藏副本**（GUI 进程，天然没有控制台），`backend/main.py` 在打印日志、抢单实例互斥体之前就处理这个参数：睡够时间 → 用 DETACHED 启动新版本 → 盯 6 秒确认它没立刻退出 → 自己退出。副本的进度行直接写到它继承的 stdout（调用方已把 stdout 指向 `update-relaunch.log`），避免在 Windows 上和父进程的追加句柄冲突导致日志写丢。帮助页与更新弹窗的文案同步改成「等几秒自动打开新版本，全程不弹命令行窗口」。
- **验证**（真实 27.0 MB exe，数据目录指向临时目录；每 100 ms 扫一遍可见的 `ConsoleWindowClass` 窗口）：一、直接跑 `--relaunch-after 3`：等待期间没有任何窗口，约 4 秒后出现主窗口、没有新控制台窗口。二、完整走 `--apply-update`：助手退出码 0、目标被替换、`MedSafeVault.exe.old` 生成，日志依次是 `waiting 4.0s before starting MedSafeVault.exe` → `started MedSafeVault.exe (pid …)` → 新实例自己的启动日志，约 4 秒后出窗口（算上两次单文件解包，从点击到窗口回来约 10 秒），全程零控制台窗口。`tools/test_updater.py` 改为断言「不再写 .bat」、助手参数是 `--relaunch-after 4 <目标>`、助手按秒数等待且能识别「刚启动就退出」。产物：版本 2.0.1，27.0 MB，`sha256 95b2a301…0031`。
